# 2026.241.2129 — feat: add the punktfunk check-verb skill

## Summary

Adds the `punktfunk` check-verb skill. The verb shipped with no entry in the skill corpus,
so no agent would discover it — the gap called out when the plugin landed.

Documents:

- **The method catalogue** (30 methods across health, native pairing, clients, library,
  virtual displays, lifecycle and the SSE `events` stream).
- **The read/write split.** Mutating methods are refused in a `check:` step and must be
  authored as `run:` steps, so a probe can never silently unpair a device or reboot a
  machine.
- **Why it is not a re-skin of `http:`** — token discovery inside the venue, domain
  semantics, and `events` as the only way to assert a *transition* rather than a state.
- **Why the request is issued inside the venue.** punktfunk binds the management API to
  loopback by design; reaching it from the host would mean republishing or relaying the
  port, weakening the posture upstream chose. This also puts the request on the same side
  as the token, and makes `curl` a real venue dependency.
- **Why the TLS flag is `verify_tls`, not `insecure`** — punktfunk serves a self-signed
  certificate, so verification must be off by default, and a Go bool cannot distinguish
  "unset" from "false"; inverting the name makes the ZERO VALUE correct.
- **That the token file is an env-file line** (`PUNKTFUNK_MGMT_TOKEN=…`), the trap that
  produced a clean 401 in live testing.

Family `check`, alongside the other probe verbs — already declared, so this one needs no
family registration.
