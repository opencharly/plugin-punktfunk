# 2026.242.1207 — feat(punktfunk): serve the headless client CLI, not just the host API

## Summary

Phase 2a of the punktfunk plan. The verb covered 30 host management-API methods and had **no client surface**, so a fleet bed could not drive the other end of a stream in charly verbs. That is precisely the gap that let Phase 1's beds pass while never pairing a client or opening a session — `pf-verb-clients` returned `[]` and it was recorded as a PASS.

Adds the documented headless `punktfunk` CLI verb list that every Linux client package ships:

| Group | Methods |
|---|---|
| saved hosts | `hosts-list` (`probe:`) `hosts-add` `hosts-forget` |
| enrolment | `pair` (`pin:`) |
| streaming | `launch` (`game:`) `open` (`auto_approve:`) `speed-test` |
| client-side reads | `client-library` `reachable` `profiles-list` |
| maintenance | `wake` `client-reset` |

They take `host:` — the documented `<host-ref>` — and run inside the venue over the same reverse channel the verb already uses for token discovery. `client_bin:` overrides the binary for the Flatpak build, which is not on PATH.

**Why the verb runs the CLI instead of a bed writing `command: punktfunk …`.** The exit-code contract gets interpreted once, here, rather than re-derived (and mis-derived) in every bed that streams:

```
0  success
2  connection failed — host unreachable or not listening
3  trust rejected — not paired (re-pair needed)
4  renderer startup failed — client could not start decode/present
5  no match for the host reference
6  interactive action required — cannot complete unattended
```

Each becomes a distinct verdict, so a bed reports *which* thing broke instead of that something did. Exit `6` is the one that matters most in automation: it means the CLI wanted a human, which is a broken unattended contract rather than a flaky run.

## Security: the PIN never reaches argv

Upstream documents `--pin <value>` as visible in the process list and `--pin -` as the scripting form. `pair` uses the stdin form, piped with `printf`:

```
printf %s '4271' | 'punktfunk' 'pair' 'host-a:47989' '--pin' '-'
```

This is the same property `TestTokenNeverReachesArgv` already asserts for the management token, and it is guarded the same way. Omitting `pin:` selects console-approval pairing instead — no `--pin` flag is invented — which is the flow an automated fleet bed wants, because no secret crosses the member boundary.

Eight new tests cover argv shapes for every method, required-field errors, the exit-code mapping, the host/client method partition, the binary override, and the two PIN properties.

**Negative control** — moving the PIN back to argv (the documented-unsafe form) fails the guard:

```
--- FAIL: TestPinNeverReachesArgv (0.00s)
    cli_test.go:23: PIN leaked into argv: [pair host-a:47989 --pin 4271]
```

**A wrong turn worth recording.** I first regenerated `params/cue_types_gen.go` through spec's `schemagen -mode=retag` pipeline, which added `yaml:` tags to every field. The committed file has **zero** yaml tags — this plugin generates with plain `cue exp gengotypes` — so that would have silently changed the marshalling of every existing field while claiming to add five. Caught by diffing before applying; the regeneration that landed removes **0** lines and adds only the new fields.

`check-live-rebuild` totals: **11 PASS, 0 FAIL**.

**What the first attempt at this bed found.** It failed, and the failure was worth having: composing the `plugin-punktfunk` candy into a client-only box drags in that candy's own baked check, which probes a punktfunk HOST's management API. There is no host in a client venue, so it can only fail. An out-of-tree verb plugin is loaded by charly from the PROJECT, not from the venue image, so the box does not need to compose it at all — the `punktfunk:` verb is available either way. Dropping it turned the bed green and is the correct composition, not a workaround.

Still not proven here, and honestly out of reach until Phase 2c: `pair`, `launch` and `speed-test`, which need a second system. `hosts-list` and `profiles-list` are the methods a host-free venue can exercise, and they are the ones that prove the dispatch path — `isCLIMethod` → `invokeCLI` → `resolveCLICall` → `runCLI` → venue exec → exit-code mapping — actually works end to end.
