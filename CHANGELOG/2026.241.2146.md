# 2026.241.2146 — fix: scrub the captured management token from source and changelog

## Summary

Removes a verbatim management token that was captured during live testing and shipped in
three merged places:

| file | form |
|---|---|
| `candy/plugin-punktfunk/token.go` | doc comment illustrating the env-file shape |
| `candy/plugin-punktfunk/token_test.go` | test fixture constant |
| `CHANGELOG/2026.241.1930.md` | carried over from the PR body at merge |

**Actual exposure: none.** The token belonged to a punktfunk host inside a disposable
container that was torn down by the same `charly check run` that produced it; it
authenticates against nothing that exists. But a credential-shaped literal has no business
in a published repo — a reader cannot tell a dead token from a live one, and neither can a
secret scanner.

Prose now shows a placeholder. The test fixture uses an obviously synthetic value, which
also makes a real point: the parser cares about the `KEY=VALUE` shape, not the value's
format, and a hex-looking fixture implied otherwise.

The `pr-validator` raised this as **T3 (embedded credential)** on the sibling skill PR
(opencharly/layer-punktfunk#3), where the same example appeared. That one is fixed on its
branch; this PR covers the places that had already merged.

The token-parsing tests still cover the real env-file shape, the bare-token shape, quoting,
CRLF, comments and multi-key ordering — the fixture *value* changed, the assertions did not,
which is what makes this a safe substitution rather than a weakened test.
