# 2026.293.1208 — feat(skills): move the punktfunk skill body beside its candy

## Summary

Moves the `punktfunk` skill body out of `candy/plugin-punktfunk/charly.yml` and into
`candy/plugin-punktfunk/.agents/skills/punktfunk/SKILL.md` — beside the candy that declares the node, which is the
directory the loader reads — leaving the `skill:` node carrying only its routing metadata.

Diff against `main`: **186 insertions and 176 deletions across two files** — the new `SKILL.md` and the manifest's
`content:` deletion. Nothing else: no script, no generated file.

### Why beside the candy, and why this can be proven now

`sdk/deploykit/skills_collect.go` resolves the tree as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`, and
`GetSourceDir()` is the directory of the candy whose manifest declares the node — here `candy/plugin-punktfunk/`.

Until this week **no command in a repo that composes no box could read a skill body**, because `CollectSkills` gates
body reads on `BoxCandyChain` — a label-size policy. That is why earlier attempts at this PR were refused on *"no
in-repo evidence exercises the changed path"*, and the finding was true. It is no longer:

- `opencharly/sdk#430` (merged, `v0.2026293.1143`) added `deploykit.CollectSkillBodies` — the same decode and resolve,
  minus the composition filter;
- `opencharly/plugin-box#57` (merged, `v2026.293.1153`) calls it from `runValidateEngine`, so `charly box validate`
  now fails on a missing or misplaced skill body.
