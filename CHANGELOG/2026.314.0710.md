# 2026.314.0710 — refactor(schema): derive the punktfunk word sets from vocabulary tables

## Summary

Convert the two inline `|` word unions in
`candy/plugin-punktfunk/schema/punktfunk.cue` to the §10.1 S3 vocabulary-table
idiom, so each closed set of words has ONE home and the enum an author meets is
`or()` of that table's keys:

```
_method  _access          (+ _methodWord / _accessWord)
```

That is the 11 `union` rows `design/dpat-baseline.tsv` records for
`plugin-punktfunk/candy/plugin-punktfunk/schema/punktfunk.cue`. **They are TWO
disjunctions, not 11:** the 43-word `method` catalog is written one alternative
per line (10 rows carry a `|`), and `access` is written on one line (1 row). The
catalog's 43rd word, `stream-probe`, closes the disjunction and carries no `|`,
so it never had a row. A union's row count is a property of its formatting, so
the row number is the only honest way to compare repos and it is not a count of
disjunctions.

`spec` is the producer and out of scope. `plugin-egress`'s 16 rows are 16

Every row this repo carried is retired by this PR; no row is left to judgement.
